№ 01

The premise

Four machines,
one object.

Every servo axis used to be a small construction project — a motor here, a driver board there, a controller somewhere behind the panel, and an encoder bolted onto the back of it all.

The M17 Series collapses that pile into a single compact package: motor, motor driver, motion controller and encoder, integrated. What leaves the enclosure is not a bundle of signal wires but one RS-485 bus, which means several motors can be daisy-chained and driven from a single connection point.

Four models — M17-60, M17-48, M17-40 and M17-34 — give you flexible options to match a particular torque and size while keeping identical control characteristics. Choose on torque and price; the code you wrote for one runs unchanged on the others.

Each motor carries the sophisticated parts too: multiple operation modes, self-calibration, and built-in status monitoring through LED indicators. Control it from any platform — Mac, PC, Raspberry Pi, Arduino, ESP32 — with nothing more exotic than a low-cost RS485 adapter, which is exactly why the same part suits a teaching lab and a production cell.

Precise position control with trapezoid movement profiles, closed-loop control mode and comprehensive error handling; standard NEMA 17 mounting; a wide 12–24 V range. Wherever precise motion is needed — robotics, CNC machines, automated test equipment, scientific instruments — it is a reliable, flexible answer.

№ 02

One bus

One pair of wires,
however many axes.

The wiring diagram of a machine usually tells you more about how it will age than the spec sheet does.

The M17 speaks RS-485. Motors are daisy-chained along the bus and controlled from one connection point, so adding a fourth axis is a matter of another short cable rather than another driver board, another heatsink and another set of step and direction lines.

On the host side, the requirement is modest: a low-cost RS485 adapter and a 12–24 V supply. A cable comes with the motor. Gearotons also sells a 3-in-1 RS485 adapter if you would rather not go shopping.

№ 06

Getting started

From pip install
to a full revolution.

The first ten minutes with an unfamiliar motor decide whether it stays on the bench or goes back in the box. These are those ten minutes, in two languages.

spin.py — Python 
import servomotor
from servomotor import M3

servomotor.open_serial_port()
motor = M3("X", time_unit="seconds",
                position_unit="degrees")
motor.system_reset()
motor.enable_mosfets()
motor.trapezoid_move(360, 2)  # one revolution in 2 s
spin.ino — Arduino 
#include <Servomotor.h>

// alias 'X' on the RS485 UART
Servomotor motor('X', Serial1);

void setup() {
  motor.setPositionUnit(PositionUnit::SHAFT_ROTATIONS);
  motor.setTimeUnit(TimeUnit::SECONDS);

  motor.systemReset();
  delay(1500);  // let the bootloader window pass
  motor.enableMosfets();
  motor.trapezoidMove(1.0, 1.0);  // one rotation, 1 s
}

void loop() {}
pip3 install servomotor Arduino IDE → Library Manager → “Servomotor”
1

Wire the bus. RS485 adapter to the motor: green is A, blue is B. Add the ground link between adapter and motors — optional, but highly recommended.

2

Power it. Anything from 12 to 24 V on the red and black pair. A cable is included with the motor.

3

Install the library. pip3 install servomotor on Mac, PC or Raspberry Pi, or add “Servomotor” from the Arduino Library Manager.

4

Meet the command set. Run servomotor_command -c to print the entire command reference in your terminal.

5

Make it move. Reset, enable the MOSFETs, then a trapezoid move — one revolution in two seconds, as above.

Units

Work in the units
you actually think in.

Encoder counts per timestep are excellent for a control loop and hopeless for a human reading a diff at midnight.

The motors use integer internal units so the motion maths stays fast. The Python and Arduino libraries convert automatically in both directions, so you can write degrees and seconds and never think about it again.

№ 08

The protocol

A protocol you can
read in an afternoon.

Good hardware has nothing to hide behind a proprietary driver. Everything the motor understands is written down, in one file, in public.

Interface
RS-485, baud rate fixed at 230400 Any number of motors daisy-chained on one bus.
Unique address
Factory-assigned 64-bit address Every motor carries one, so it can always be addressed individually — even before you have configured anything.
Alias
1 byte, 0–251 Give a motor a short alias to keep packets small while still addressing it individually. 255 is the broadcast alias.
Command set
Comprehensive Motion control, configuration and status monitoring, all covered.
Firmware update
Over the same RS-485 interface No programmer, no disassembly, no separate cable.

№ 09

On the back

Two lights,
two buttons.

Before a single line of your software runs, the motor is already telling you what it is doing — and it will spin on its own if you ask it nicely.

Green LED
Heartbeat, boot state & bus traffic Flashes slowly as a heartbeat. Flashes quickly to tell you the bootloader is running rather than the application. Lights up briefly while a packet is being received, so it flickers with communication on the bus.
Red LED
Fatal errors Flashes a certain number of times to indicate a fatal error code. Silent when all is well.
Reset button
Restart, clean Restarts the microcontroller and returns all state to defaults.
Test button
Spin it by hand A brief press spins the motor one way. Press for more than 0.3 s and release to spin the other way. Hold at least 2 s and release to enter closed-loop mode. Hold more than 15 s and release to run a self-calibration.

The motor spins during calibration and must be able to turn freely — remove any load first.
