The integration

Four systems.
One housing.

A conventional axis is four purchases and three wiring harnesses: a stepper, a driver board, a motion controller and an encoder. The M17 is all of it, in a package nearly the same size as the stepper it replaces — and with no protrusions to design around.

Trapezoid move profiles Closed-loop mode Self-calibration Status monitoring Comprehensive error handling

One bus

One bus.
Every axis.

Adding the tenth motor works exactly like adding the first. Every M17 speaks RS-485, so you daisy-chain them on one pair of wires and drive the whole machine from a single connection point — no controller per axis, no pulse train to schedule.

  • —One connection point. Any number of motors share the bus, powered from a common 12–24 V supply.
  • —Always addressable. Each motor carries a factory-assigned 64-bit unique address, plus an optional 1-byte alias.
  • —Any host. Mac, PC, Raspberry Pi, Arduino or ESP32 — all you add is a low-cost RS485 adapter.

A complete bench setup: host, RS485 adapter, motors in a chain, one power supply.

Four models

Same footprint.
Four torque points.

M17-60, M17-48, M17-40 and M17-34 share a 42.2 × 42.2 mm body, a 5 mm shaft, one command set and identical control characteristics. Torque is what separates them — 0.65 down to 0.28 N·m — and with it the height and the weight.

Pick the smallest one that moves your load. Everything you write for it runs unchanged on the other three.

spin.py 
import servomotor
from servomotor import M3

servomotor.open_serial_port()
motor = M3("X", time_unit="seconds",
                position_unit="degrees")
motor.system_reset()
motor.enable_mosfets()
# one revolution in 2 s
motor.trapezoid_move(360, 2)
spin.ino 
#include <Servomotor.h>

// alias 'X' on the RS485 UART
Servomotor motor('X', Serial1);

void setup() {
  motor.setPositionUnit(
      PositionUnit::SHAFT_ROTATIONS);
  motor.setTimeUnit(TimeUnit::SECONDS);

  motor.systemReset();
  // let the bootloader window pass
  delay(1500);
  motor.enableMosfets();
  // one rotation in one second
  motor.trapezoidMove(1.0, 1.0);
}

void loop() {}

Unit system

Your units.
Not the motor’s.

The motors work in integer internal units so the motion maths stays fast. The Python and Arduino libraries convert for you, so you write degrees, seconds and amps — or rotations, timesteps and encoder counts, if that is how you think.

Communication protocol

A bus you can learn
in an afternoon.

RS-485, one fixed baud rate, one command set, and a machine-readable definition of every command. Nothing to reverse-engineer.

  • —230400 baud, fixed. No auto-negotiation, no per-device configuration.
  • —Any number of motors daisy-chained on a single bus.
  • —64-bit unique address assigned at the factory, so a motor can always be addressed individually.
  • —1-byte alias, 0–251, keeps packets short while still addressing one motor. 255 is the broadcast alias.
  • —Firmware update over RS-485 is supported — no disassembly, no programmer.
  • —A comprehensive command set covering motion control, configuration and status monitoring.

On the motor

Two LEDs, two buttons,
no console required.

Everything you need to know about a motor is on the motor. Diagnose a bus without a laptop, and spin a shaft before you have written a line of code.

  • Green LEDFlashes slowly as a heartbeat, quickly to indicate that the bootloader is running rather than the application, and lights up briefly while a packet is being received — so it flickers with traffic on the bus.
  • Red LEDIndicates fatal error codes by flashing a certain number of times.
  • Reset buttonRestarts the microcontroller and returns all state to defaults.
  • Test buttonA brief press spins the motor one way. Press for more than 0.3 s and release to spin the other way. Hold at least 2 s and release to enter closed-loop mode. Hold more than 15 s and release to run a self-calibration.

The motor spins during calibration and must be able to turn freely — remove any load first.
