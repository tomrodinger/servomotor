§ 02  ·  What is inside
Integration

Four boxes on the bill of materials.
Now one.

The M17 Series puts the motor, the motor driver, the motion controller and the encoder into a single compact package — nearly the same size as the NEMA 17 stepper of the same specification, with nothing sticking out of it.

01  Component

Motor

Brushless, four sizes, the same torque-to-weight ratio as an equivalent stepper.

02  Component

Driver

Power stage on board. No external driver card, no wiring loom between the two.

03  Component

Motion controller

Trapezoid profiles are computed in the motor. You send the destination.

04  Component

Encoder

Position feedback for closed-loop control and for self-calibration.

Also inside

Protection, on every unit

Integrated over-current, over-voltage and over-temperature protection, backed by comprehensive error handling — the motor watches its own current, voltage and temperature and reports what it finds.

Also inside

Modes, calibration, status

Multiple operation modes, self-calibration, and built-in status monitoring reported through the LED indicators and over the bus.

§ 03  ·  The bus
RS-485 daisy chain

One pair of wires.
Every axis on it.

Motors chain from one to the next and answer to a single connection point. Adding an axis means adding a motor to the chain — not another driver, another heatsink and another set of step-and-direction lines.

Fig. 2  ·  Typical connection

Computer  ·  RS485 adapter  ·  motors in chain  ·  12–24 V supply

01  Topology

Any number of motors

Daisy-chain the whole machine on one RS-485 interface and control it from one connection point.

02  Interface

One low-cost adapter

Mac, PC, Raspberry Pi, Arduino or ESP32 — all any of them needs is an inexpensive RS485 adapter.

03  Commands

Words, not pulses

“Enable MOSFETs.” “Trapezoid move.” No timing-critical DIR/STEP generation on your side.

§ 06  ·  Getting started
Python  /  Arduino

Import the library.
Move the shaft.

Two libraries, one command vocabulary. Both handle the packet framing and the unit conversion, so the first program you write is the program that spins the motor.

L01  Python  ·  spin.py 
import servomotor
from servomotor import M3

servomotor.open_serial_port()
motor = M3("X", time_unit="seconds",
                position_unit="degrees")
motor.system_reset()
motor.enable_mosfets()
motor.trapezoid_move(360, 2)  # one revolution in 2 s
pip3 install servomotor
G  Five steps to first motion
  1. 01Fit a low-cost RS485 adapter to your Mac, PC, Raspberry Pi, Arduino or ESP32.
  2. 02Wire the included cable and a 12–24 V supply to the motor.
  3. 03Install the library — pip3 for Python, Library Manager for Arduino.
  4. 04Give the motor a 1-byte alias so packets stay short.
  5. 05Enable the MOSFETs and send a trapezoid move.
Getting-started guide →
L02  Arduino  ·  spin.ino 
#include <Servomotor.h>

Servomotor motor('X', Serial1);      // alias 'X' on the RS485 UART

void setup() {
  motor.setPositionUnit(PositionUnit::SHAFT_ROTATIONS);
  motor.setTimeUnit(TimeUnit::SECONDS);

  motor.systemReset();
  delay(1500);                       // let the bootloader window pass
  motor.enableMosfets();
  motor.trapezoidMove(1.0, 1.0);     // one rotation in one second
}

void loop() {}

§ 07  ·  Unit system
Seven quantities

Work in your units.
The library does the arithmetic.

The motors use integer units internally so the motion maths stays fast. The libraries convert in both directions, so you never have to.

U01  Time

seconds · milliseconds · minutes · microseconds · timesteps

U02  Position

shaft rotations · degrees · radians · encoder counts

U03  Velocity

rotations per second · RPM · degrees per second · radians per second · counts per second · counts per timestep

U04  Acceleration

rotations per second² · RPM per second · degrees per second² · radians per second² · counts per second² · counts per timestep²

U05  Current

internal current units · milliamps · amps

U06  Voltage

volts · millivolts

U07  Temperature

celsius · fahrenheit · kelvin

Note

Integer inside, human outside

Declare the units once when you create the motor object. Every command and every reading after that speaks them.

§ 08  ·  Communication protocol
RS-485

230400 baud.
Sixty-four bits of address.

A fixed, unambiguous bus. Every motor is individually addressable out of the box, and every motor can be updated in place without leaving the chain.

P01  Baud rate

230400

Fixed. Nothing to negotiate, nothing to mis-set.

P02  Unique address

64 bit

Factory-assigned to every motor, so it can always be addressed individually.

P03  Alias

0 – 251

A 1-byte alias keeps packets short while still addressing one motor. 255 is the broadcast alias.

P04  Chain

Any number of motors

All daisy-chained on one bus, all reachable from one connection point.

P05  Firmware

Update over the bus

Firmware update over the RS-485 interface is supported — no disassembly, no programmer.

P06  Command set

Comprehensive

Motion control, configuration and status monitoring, all covered.

§ 09  ·  Indicators & controls
Rear face

Two LEDs.
Two buttons.

Enough to tell you what the motor is doing, and enough to make it move, before you have written a single line of code.

Fig. 4  ·  Rear face
I01  Green LED

Heartbeat & traffic

  • Slow flashRunning, alive
  • Fast flashBootloader, not the application
  • Brief lightReceiving a packet

So it flickers with the traffic on the bus.

I02  Red LED

Fault codes

  • Flash countFatal error code

Reserved for fatal errors. The number of flashes identifies the code.

I03  Reset button

Back to defaults

Restarts the microcontroller and returns all state to defaults.

I04  Test button

Spin it by hand

  • Brief pressSpins one way
  • Press > 0.3 s, releaseSpins the other way
  • Hold ≥ 2 s, releaseEnters closed-loop mode
  • Hold > 15 s, releaseRuns a self-calibration
Caution

The motor spins during calibration and must be able to turn freely. Remove any load before you start one.
