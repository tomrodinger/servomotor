$ 01 — quickstart

One line to install.
Five to move a shaft.

The Python and Arduino libraries speak the same protocol and expose the same verbs. Open the port, name the motor, reset it, energise it, tell it where to go. There is no pulse train to generate and no step timing to get wrong.

bash install 
$ pip3 install servomotor      # yes, that is the whole install
$ servomotor_command -c        # print the full command reference
spin.py python 
import servomotor
from servomotor import M3

servomotor.open_serial_port()
motor = M3("X", time_unit="seconds",
                position_unit="degrees")
motor.system_reset()
motor.enable_mosfets()
motor.trapezoid_move(360, 2)  # one revolution in 2 s
spin.ino arduino 
#include <Servomotor.h>

Servomotor motor('X', Serial1);   // alias 'X' on the RS485 UART

void setup() {
  motor.setPositionUnit(PositionUnit::SHAFT_ROTATIONS);
  motor.setTimeUnit(TimeUnit::SECONDS);

  motor.systemReset();
  delay(1500);                 // let the bootloader window pass
  motor.enableMosfets();
  motor.trapezoidMove(1.0, 1.0);  // one rotation in one second
}

void loop() {}

$ 02 — unit system

Integers on the wire.
Your units in your code.

$ 03 — communication protocol

RS-485.
Fixed at 230400 baud.

A small, documented command set over a two-wire bus. Nothing proprietary to license, nothing to reverse-engineer, and one JSON file that is the single source of truth.

Baud rate
230400, fixed. No negotiation, no auto-baud, no surprises on a long cable run.
Bus topology
Any number of motors daisy-chained on one bus and driven from a single connection point.
Unique address
Every motor carries a factory-assigned 64-bit unique address, so it can always be addressed individually — even before you have configured anything.
Alias
Give a motor a 1-byte alias (0–251) to keep packets short while still addressing it individually.
Broadcast
Alias 255 is the broadcast address: one packet, every motor on the bus.
Firmware update
Supported over the RS-485 interface — the same two wires you already use for motion.
Command set
Comprehensive coverage of motion control, configuration and status monitoring, organised into five groups:
01Basic Control 02Motion Control 03Configuration 04Status & Monitoring 05Device Management
Source of truth
The command definitions live in motor_commands.json, in the repository:
github.com/tomrodinger/servomotor/​blob/main/python_programs/servomotor/motor_commands.json
…or print the whole reference locally with servomotor_command -c

$ 04 — topology

One connection point.
Every axis behind it.

Power and data run down the chain from motor to motor. Add an axis by plugging in another motor and giving it an alias — not by adding another driver board, another set of step and direction pins, and another thing to wire wrongly.

$ 05 — integration

Four subsystems.
One housing.

An M17 is a motor, a motor driver, a motion controller and an encoder in a single compact package — nearly the size of the NEMA 17 stepper of the same specification it replaces, with no protrusions to design around. Four models — M17-60, M17-48, M17-40 and M17-34 — cover the torque range while keeping identical control characteristics, so a machine can mix sizes and run one code path.

Precise position control with trapezoid movement profiles, closed-loop mode, self-calibration, built-in status monitoring and comprehensive error handling — all of it addressable from a Mac, a PC, a Raspberry Pi, an Arduino or an ESP32 with nothing more than a low-cost RS485 adapter.

$ 09 — indicators & controls

Two LEDs.
Two buttons.

Enough of a user interface to tell you what the motor is doing before you have written a single line of code — and to spin it without a host at all.

> status LEDs

Green
Flashes slowly as a heartbeat. Flashes quickly when the bootloader is running rather than the application. Lights up briefly while a packet is being received, so it flickers with traffic on the bus.
Red
Indicates fatal error codes by flashing a certain number of times.

> buttons

Reset
Restarts the microcontroller and returns all state to defaults.
Test
Spins the motor, by press duration:
  • brief press — spins one way
  • > 0.3 s, then release — spins the other way
  • ≥ 2 s, then release — enters closed-loop mode
  • > 15 s, then release — runs a self-calibration

NOTE   The motor spins during calibration and must be able to turn freely — remove any load first.
